## 1. 项目概述与产品定位

### 1.1 一句话定位
一个让信息学竞赛学生在浏览器上**刷笔试题、做模拟考、看解析、清错题、看进度**的轻量训练网站，专注 CSP-J/S 第一轮（初赛笔试）与 NOI 笔试备考。

### 1.2 与 OJ（在线判题平台）的本质区别
本项目**不是**代码评测平台：不出编程题、不编译不运行代码、不判运行结果。

| 维度 | OJ 平台 | 本项目 |
| --- | --- | --- |
| 题目形态 | 编程题（读题→写代码→评测） | **选择题 / 判断题 / 填空题**（笔试题） |
| 判分方式 | 编译运行、比对输出 | **答案比对**（多选全对、填空归一化匹配） |
| 核心场景 | 写代码能力训练 | **知识记忆、理解辨析、考试熟练度**训练 |
| 反作弊/保密 | 代码查重 | 交卷后出成绩、考试期间不展示答案 |

### 1.3 目标赛事背景（内容设计依据）
- **CSP-J/S 第一轮（初赛）**：笔试/机考形式，题型为单项选择、判断题、阅读程序题（选择/判断）、完善程序（填空）—— 这是最大量用户群。
- **NOI 笔试**：选手须通过的笔试题（选择题+判断题），计入总分。
- **NOIP**：现行赛制以机试为主，但**历年真题与知识点**仍以笔试题形式被广泛用于日常训练，题库保留该分类。

### 1.4 产品原则（贯穿全站）
1. **即时反馈**：练习模式做完即判、即看解析，强化记忆。
2. **低门槛**：注册即可用，无需配置环境，浏览器打开即刷题。
3. **数据驱动**：错题自动沉淀，统计反映薄弱分类，引导学生针对性复习。
4. **考试真实感**：模拟考有计时、有自动交卷、考后统一出成绩，还原考场节奏。

## 2. 目标用户画像

### 2.1 主用户：初中/高中竞赛学生（占 90%）
- **Persona A ——「初赛冲刺生」**（主力用户）
  - 画像：初中生为主，备赛 CSP-J（入门级），部分备赛 CSP-S；每天可支配训练时间 0.5~2 小时。
  - 痛点：初赛知识点杂（语言、数据结构、算法、数学、计算机史），不知道自己的薄弱分类；纸质真题做一遍就丢，错题无法沉淀。
  - 目标：考前 1~3 个月高强度刷题 + 模拟考，快速提升正确率。
- **Persona B ——「长期训练生」**
  - 画像：高中生，系统学习信息学 1 年以上，日常刷题保持手感，备战 CSP-S 第一轮 / NOI 笔试。
  - 痛点：需要按分类/难度精细化训练；希望看到长期进度曲线。
  - 目标：分类突破 + 模拟考验证水平。
- **Persona C ——「考前突击生」**
  - 画像：临近初赛 1~2 周才开始刷题，时间紧。
  - 痛点：没时间系统学，只想做**真题模拟卷 + 看解析**。
  - 目标：模拟考试模式 + 错题重练，用最短时间过一遍高频考点。

### 2.2 次要用户：信息学老师/教练（占 10%，MVP 可不针对）
- 希望布置训练任务、查看学生整体进度 —— **MVP 不做班级/布置功能，后续版本考虑**。

### 2.3 使用场景
- 课间/午休/晚自习碎片时间：练习模式刷 10~20 题。
- 周末整块时间：做一套 40 分钟模拟卷。
- 考前一天：只看错题本 + 重练错题。

### 2.4 用户核心诉求（按优先级）
1. 有足够多、足够准的笔试题可刷（P0：种子题库 + 分类完整）。
2. 做完立刻知道对错和为什么错（P0：即时判分 + 解析）。
3. 知道哪里弱（P0：分类统计 + 错题本）。
4. 考前能模拟真实考试（P0：模拟考 + 计时 + 自动交卷）。
5. 进度跨设备不丢（P0：账号系统 + 服务端存储）。

## 3. 核心功能清单

> 优先级标注：**P0 = MVP 必须做**；P1 = MVP 建议做（资源允许则进首版）；P2 = 后续版本。

### F1 用户系统（P0）
- F1.1 注册（用户名 + 密码 + 确认密码；用户名唯一）。
- F1.2 登录 / 退出登录（JWT 鉴权，登录态持久化）。
- F1.3 个人资料（MVP 极简：仅展示用户名；头像/昵称修改放 P1）。
- F1.4 登录保护：未登录用户可浏览题库列表，但**答题、考试、错题、统计需登录**（P0 决策：降低首访门槛）。

### F2 题库系统（P0）
- F2.1 **分类体系**（一级分类，MVP 固定 6 类，数据可扩展）：
  1. C++ 语言基础（语法、类型、运算符、输入输出、作用域、STL 基础）
  2. 数据结构（数组、链表、栈、队列、树、图、哈希、堆）
  3. 算法（排序、二分、递归、贪心、DP、搜索、图论、字符串）
  4. 数学（数论、组合数学、概率、进制、逻辑）
  5. 计算机基础（硬件、操作系统、网络、编码、计算机史与人物、竞赛常识）
  6. NOI 相关知识（NOIP/CSP/NOI 历年真题、赛制规则、OI 竞赛常识）
- F2.2 **二级筛选维度**（P0 至少支持一级分类筛选 + 题型筛选；难度筛选 P1）：
  - 难度：入门 / 提高（P1 上难度字段，P0 数据可不填难度）。
- F2.3 **题型**（P0 全部支持）：
  - 单选题（4 个选项，唯一答案）
  - 多选题（4~5 个选项，1 个以上正确答案，全对才得分）
  - 判断题（正确 / 错误）
  - 填空题（文本答案，支持多个等价答案，判分做模糊归一化）
- F2.4 **题目字段**（供架构师建表，详见 §7）：
  - 题干（含代码片段/选项内代码，用 Markdown 或纯文本 + 代码块渲染）
  - 选项（多选/单选）、判断题无选项
  - 正确答案、答案解析、知识点标签（关联分类）、难度、来源（原创/真题/模拟）
  - 状态字段（启用/停用，P1 管理端用）
- F2.5 题库列表页：分类 Tab + 题量显示 + 分页/加载更多（P0 数据量小，分页即可）。

### F3 刷题练习模式（P0，核心主功能）
- F3.1 进入方式：题库列表 → 选分类 → 「开始练习」；或「随机练习」（全题库随机 N 题，P0 支持随机）。
- F3.2 练习流程：单题一屏作答 → 提交 → **立即判分 + 立即展示解析** → 下一题（可选「下一题」/「直接下一题」）。
- F3.3 作答交互：
  - 单选/判断：点选即提交（可配置，MVP 用「选择 → 点提交」两步，避免误触）。
  - 多选：勾选多个 → 提交。
  - 填空：文本框输入 → 提交。
- F3.4 答题结果反馈：对（绿色）/ 错（红色），显示正确答案、我的答案、解析、所属分类/知识点。
- F3.5 练习记录：每次练习会话记入答题记录（题目、答案、对错、用时）。
- F3.6 未登录用户：可先匿名体验少量练习（P1 可选，MVP 直接要求登录，简化实现）。

### F4 模拟考试模式（P0）
- F4.1 **组卷**（MVP 简化规则，P1 支持自定义）：
  - 系统按预设规则组卷：从选定分类（默认全题库）随机抽取，题型结构参照 CSP-J 初赛：单选 15 题 + 判断 10 题 + 填空 5 题（题量与结构可在种子配置中调整）。
  - 提供 2~3 套预设卷（如「CSP-J 模拟卷一/二」），P1 支持用户自定义题量。
- F4.2 **计时**：整卷限时（默认 40 分钟，可配置）；页面显示倒计时；最后 5 分钟变红提示。
- F4.3 **交卷**：手动交卷（未答完提示）或**时间到自动交卷**（未答按错/跳过计，MVP 决策：未答题计 0 分）。
- F4.4 **考后出分**：交卷后统一判分，展示成绩单：总分、得分、正确题数、各题型得分、各分类得分；**考试期间不显示答案**（防止边考边查）。
- F4.5 考后解析：成绩单可逐题查看解析（与练习模式一致），错题自动进错题本。

### F5 答题与判分（P0，正确性关键）
判分规则（架构与后端必须严格实现，测试按此验收）：
| 题型 | 判分规则 | 示例 |
| --- | --- | --- |
| 单选题 | 答案完全一致得满分，否则 0 分 | 标准答案 B，选 B 得 1 分 |
| 判断题 | 正确/错误一致得满分，否则 0 分 | 答案「正确」，选「正确」得 1 分 |
| 多选题 | **全对才得分**（全选且无多余选项）；漏选/多选/错选均 0 分 | 答案 AB，选 AB 得 2 分；选 A、ABC、AC 均 0 分 |
| 填空题 | 归一化后完全匹配得满分；**模糊匹配**（去首尾空白、全半角归一、大小写归一；数字等价如 `2n` 与 `2*n` 可作为等价答案录入） | 答案 `O(n)`，输入 `O(n)`、`o(n)` 均得分 |

- 每道题分值：默认单选/判断 1 分、多选 2 分、填空 2 分（可在题目/试卷配置中调整，MVP 用默认值）。
- 判分在**服务端**完成（前端只展示，不做可信判分）。

### F6 答案解析（P0）
- F6.1 练习模式：提交后立即展示（答案 + 解析 + 知识点标签）。
- F6.2 模拟考：交卷后统一展示。
- F6.3 解析内容：正确选项说明 + 错误选项排除理由 + 涉及知识点；代码类题目给出代码讲解（Markdown 渲染）。

### F7 错题本（P0）
- F7.1 **自动收录**：练习与考试中答错的题自动进错题本（同一题去重，记录最近答错时间与次数）。
- F7.2 错题列表：按分类筛选、按时间倒序、显示答错次数。
- F7.3 **错题重练**：对错题重新作答（模式与练习一致），答对后可选择「移出错题本」（P0：答对一次即自动标记为已掌握并建议移除，用户可手动移除）。
- F7.4 错题数统计：首页/个人页展示待复习错题数。

### F8 学习进度统计（P0）
- F8.1 总览指标：累计做题数、正确题数、总体正确率、待复习错题数、完成模拟考次数。
- F8.2 **分类掌握度**：按 6 大分类分别统计做题数与正确率（雷达图或条形图，前端可视化）。
- F8.3 近期趋势：最近 7 天每日做题数与正确率（P1，MVP 可只做 F8.1+F8.2）。
- F8.4 统计口径（架构需固化）：正确率 = 答对题数 ÷ 已判分题数；同一题多次作答均计入；模拟考与练习记录合并统计。

### F9 管理后台（P2，MVP 不做）
- 题目在线新增/编辑/停用、分类管理、试卷配置、用户管理。
- MVP 题库内容通过**种子数据（SQL/JSON 脚本）**初始化，管理端接口 P2。

## 4. MVP 范围界定

### 4.1 MVP 必须做（P0）—— 首版交付清单
1. 用户注册 / 登录 / 退出（JWT）。
2. 题库：6 大分类 + 4 种题型（单选/多选/判断/填空），种子数据每分类 ≥ 10 题、总题量 ≥ 60 题，全部带答案与解析。
3. 练习模式：分类选题、随机练习、单题作答、即时判分、即时解析。
4. 模拟考试：预设卷组卷、倒计时、自动交卷、考后统一判分、成绩单、考后解析。
5. 判分规则：单选/判断精确匹配、多选全对才得分、填空归一化+模糊匹配（服务端判分）。
6. 错题本：自动收录、分类筛选、错题重练、移除。
7. 统计：累计做题、正确率、分类正确率、待复习错题数。
8. 响应式 Web（桌面优先，平板可用），前端按设计规范实现。

### 4.2 MVP 建议做（P1，资源允许进首版）
- 难度筛选（入门/提高）、题目标签。
- 最近 7 天学习趋势图。
- 匿名体验模式（未登录试刷 10 题）。
- 用户自定义模拟考组卷（选分类、题量、时长）。
- 模拟考成绩历史列表（多次考试对比）。

### 4.3 后续版本（P2）
- 管理后台（题目 CRUD、试卷管理、用户管理）。
- 题目批量导入（JSON/Excel）、真题卷按年归档。
- 知识点图谱、薄弱点智能推荐刷题。
- 班级/老师布置作业与学情统计。
- 排行榜、成就徽章、连续打卡。
- 移动端 App / PWA 离线刷题。

### 4.4 MVP 明确**不做**（防止范围蔓延）
- 不做编程题、不做代码评测/运行环境。
- 不做社交/评论/讨论区。
- 不做付费/会员体系。
- 不做精细权限（仅普通用户；管理端 P2）。
- 不做邮件/手机验证（注册仅用户名+密码）。

## 5. 用户故事与典型使用流程

### 5.1 用户故事（As a … I want … so that …）
1. 作为初赛冲刺生，我要按分类刷题，以便集中攻克「数据结构」薄弱点。
2. 作为初赛冲刺生，我提交答案后要立刻看到对错和解析，以便当场理解知识点。
3. 作为长期训练生，我要做带倒计时的模拟卷，以便检验 40 分钟内能否完成并保持正确率。
4. 作为考前突击生，我要在交卷后看到各分类得分，以便考前最后一天只复习弱分类。
5. 作为所有学生，我答错的题要自动进错题本，以便考前集中重练。
6. 作为所有学生，我要看到总体正确率和各分类正确率，以便知道进步与否。

### 5.2 端到端典型流程（练习主链路）
```
注册/登录
   → 首页（概览：继续练习 / 模拟考试 / 错题本 / 统计）
   → 题库页：选择分类「数据结构」→ 点「开始练习」
   → 答题页：第 1 题（单选题）选择 B → 提交
      → 立即判分：✓ 绿色反馈 + 显示解析 + 「下一题」
   → …循环至本组题做完（或退出）
   → 返回首页：错题本出现本次错题，统计页正确率更新
```

### 5.3 模拟考试流程
```
首页 → 模拟考试 → 选择「CSP-J 模拟卷一」
   → 考试页：40:00 倒计时，逐题作答（可跳题，答题卡显示已答/未答）
   → 时间到自动交卷（或手动交卷）
   → 成绩单：总分 / 得分 / 各题型得分 / 各分类正确率
   → 逐题查看解析；错题自动入错题本
```

### 5.4 错题复习流程
```
首页 → 错题本 → 按分类筛选
   → 选择「重练错题」→ 逐题作答（答对标记已掌握）
   → 手动移出或自动移出已掌握的错题
   → 错题本数量减少
```

### 5.5 权限与边界行为（测试验收用）
| 场景 | 预期行为 |
| --- | --- |
| 未登录访问答题页 | 跳转登录页（或提示登录后继续） |
| 未登录访问错题本/统计 | 跳转登录页 |
| 考试中超时 | 自动交卷，未答题计 0 分 |
| 提交多选只选一个 | 按多选规则判 0 分（漏选） |
| 填空输入带空格/全角 | 归一化后匹配，正常判分 |
| 空题库分类 | 提示「该分类暂无题目」，不报错 |

## 6. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 平台 | Web 应用，桌面浏览器为主（Chrome/Edge 最新 2 个版本），平板可用，不做 IE |
| 响应式 | ≥ 1024px 完整布局；768~1024px 可用布局不破损 |
| 性能 | 页面加载 < 2s（本地部署）；答题提交判分 < 300ms；题库列表 1000 题内流畅 |
| 可用性 | 全部核心流程无阻断性 bug；错误提示文案清晰（中文） |
| 数据安全 | 密码 bcrypt 哈希存储；JWT 鉴权；API 服务端校验权限 |
| 数据持久化 | SQLite（本地文件，随项目一键初始化），题目种子数据可重复初始化不报错 |
| 可部署性 | 一键启动（README 含依赖安装、初始化、启动命令），默认本地端口，前后端分离 |
| 代码质量 | 前后端源码可运行、无明显 bug；关键判分逻辑（多选、填空归一化）有测试覆盖 |

## 7. 数据与内容策略（给架构师/后端的建表输入）

### 7.1 核心实体（架构文档据此细化）
1. **users**：id、username（唯一）、password_hash、created_at。
2. **categories**：id、name（6 大分类）、sort_order。
3. **questions**：id、category_id、type（single/multiple/judge/fill）、difficulty（P1）、stem（题干，含 Markdown）、options（JSON 数组，单选/多选用）、answer（单选/判断存答案；多选存答案数组 JSON；填空存等价答案数组 JSON）、analysis（解析）、source（原创/真题/模拟）、enabled。
4. **practice_sessions / practice_records**：练习会话与逐题答题记录（user_id、question_id、user_answer、is_correct、answered_at、duration_ms）。
5. **exams**（试卷模板）：id、name、duration_minutes、config（题型题量 JSON）。
6. **exam_sessions**：id、user_id、exam_id、started_at、submitted_at（NULL=进行中）、auto_submitted、total_score、score。
7. **exam_answers**：exam_session_id、question_id、user_answer、is_correct、score。
8. **wrong_questions**：id、user_id、question_id、wrong_count、last_wrong_at、mastered（已掌握标记）。

### 7.2 种子题库要求（后端 t4 必须满足）
- 6 大分类每类 ≥ 10 题，总题量 ≥ 60 题。
- 每类包含：单选、多选、判断至少各 1 题；全库含若干填空题。
- 每题必须带答案与解析；多选答案必须为 2 个及以上选项；填空支持等价答案（如 `O(n)` / `O(nlogn)` 等）。
- 内容准确、贴合 CSP-J/S 初赛难度（示例：C++ 中 `int` 占 4 字节、栈的后进先出、二分查找时间复杂度、`(A+B)+C=A+(B+C)` 结合律、ASCII 码、NOI 赛制等）。

### 7.3 统计口径（固化，避免实现分歧）
- 正确率 = 答对题数 ÷ 已判分题目总数（练习 + 模拟考均计入）。
- 分类正确率 = 该分类答对题数 ÷ 该分类已判分题数。
- 模拟考成绩独立记录，不计入练习正确率（但计入「累计做题数」与「错题本」）。
- 错题本：同题去重；答对一次自动标记已掌握，仍保留展示，用户可手动移除。

## 8. MVP 验收标准（给测试评审员 t6 使用）

1. 注册 → 登录 → 浏览题库 → 练习答题 → 即时判分 → 查看解析，全链路走通。
2. 模拟考试：组卷 → 计时 → 手动/自动交卷 → 成绩单 → 考后解析，全链路走通。
3. 判分正确性：单选、判断、多选（漏选/多选/错选均 0 分）、填空（含等价答案、大小写/空白归一化）逐一验证，含答错场景。
4. 错题自动收录、重练、移除生效；统计数字（总做题、正确率、分类正确率）与真实作答一致。
5. 边界：未登录访问受保护页面跳转登录；空分类提示友好；考试超时自动交卷且未答计 0 分。
6. 种子数据 ≥ 60 题、6 分类齐全、每类覆盖 3 种题型以上、答案与解析完整。
7. 前端视觉与 docs/design.md 一致（色值、布局、组件）；桌面与平板分辨率无布局破损。
8. 产出 docs/test-report.md，结论明确：是否达到 MVP 可交付标准。
